# First native state-storage slice

`tools/ram_map.py` generates module structs and an address projection alongside
the RAM accessor backing. A variable's `host_module` selects its owner in
`CT_VARS_HOST`; emulator-backed builds retain their byte layout. The map rejects
shared bytes, overlapping record fields, unchecked tables and page instances
selected for migration. Native typed accessors reach the struct fields directly,
while saves, raw helpers and video sources use a generated byte view of the
same fields; a native route driver's `peek`/`watch` would call the same view
(STATE.md; `ct_drive` still peeks the emulated bus). The work-RAM streaming port uses that view too; no
duplicate field values are synchronized with the residual image.

The worked slice is the four location records, 20 serialized bytes, including
the three records a cartridge save restores. `tools/ram_map.py storage` measures
2,259/2,263 variables still image-backed (99.82%), down from 100%. The denominator
counts variables, not fields or bytes; the residual allocation remains 128 KiB.
`vars_host_test` checks mirrored, partial and bulk accesses, video sourcing and
actual save/load/checksum routines with a committed `.srm`, without a ROM.
The reproducible source/alias inventory and mechanism are in [STATE.md](../STATE.md);
TODO.md lists ownership work for the remaining modules.

## First slice selection

The location module owns four records: `location`, `location_previous`,
`location_stored`, `location_next` (20 declared bytes). Location logic already
uses typed accessors; these records have no aliases, unchecked accessors, page
instances or video sources. They cross module boundaries through those
accessors, with `core` as their map subsystem because all modes share them.
Generic memory operations remain compatibility clients, not additional owners.
Three records lie in the saved-game projection, while the next location does
not. This exercises persistence and the route driver's most useful address
without first rewriting any ports. Whole subsystems with scratch reuse are
deliberately deferred; TODO.md lists their prerequisites.

## First-slice validation

The sampled gate (`tools/suite.py --ct-dev build/main/ct_dev -j 2 --evidence`)
ended with **`suite OK`**: 37/37 shadow movies clean, 37/37 native movies ending
with a picture, and 37/37 recorded-outcome ratchet passes in both strict and
native modes. These preserve the recorded tolerances; they do not assert that
native playback matches every reference outcome. The generated-only trace
comparison was identical over 7,200 frames. No baseline or exception was added.

The warning-as-error build passed. The Python suite passed 593 tests; the
subsequent inventory regression tests and RAM-map tests passed together (37
tests). `ram_map.py accessors --check`, `vars_host_test`, `native_time_test`
and the emulator-backed `vars_test` passed. The `field` movie with
`ct_dev --native on --px-check-services` reported 11,402/11,402 frames
identical, zero differing lines and zero pixels. Gate logs and derived
artifacts remain under the ignored build directory; the evidence cache is
local to the worktree.
